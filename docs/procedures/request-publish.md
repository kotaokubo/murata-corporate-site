# 手順書：本番への公開を依頼する

前提：作業ブランチを `staging` へ入れ、検証用の URL で、事務の方と公開判断者が確かめ終わっていること。

1. **同じ作業ブランチから** `main` へ PR を出す（`staging` から出さない）
2. PR テンプレートの「確かめたこと」と「公開を判断した人」を埋める
3. 必須チェックの「staging-verified」が失敗したら、次のどちらか
   - 検証のあとに直しを足したのに `staging` へ入れ直していない → もう一度 `staging` へ PR を出して確かめてもらう
   - `main` への PR を `staging` へ入れる前に出した → `staging` へ入れてから、PR の Checks 画面で「Re-run」を押す（`staging` が変わっても、このチェックは自動ではやり直されない）
4. 必須チェックがすべて緑になるのを待つ。`codex-review` は Codex のレビューが付くまで最大25分待つ。Codex の指摘があれば直すか理由を返信して、すべて解決（Resolve）する。区分 B を含む PR は、大久保の承認（Approve）も待つ
5. **事務の方が** PR の画面で「Merge pull request」を押す。マージ方法は「Create a merge commit」（これしか選べない設定になっている）
   - AI に「本番にリリースして」と頼んでもよい。AI は、出す内容（PR の番号、題名、変更の要約、公開を判断した人）を見せて確認を求めてくるので、内容を確かめて「はい」と答える。必須チェックや承認が足りないときは、AI はマージせずに理由を伝える
6. 数分で本番に反映される。本番の URL で表示を確かめる
7. 誤って公開したときは、自分や AI で直そうとせず、すぐ大久保へ連絡する
